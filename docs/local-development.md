# Локальная разработка

Проект использует Docker Compose для инфраструктуры и Taskfile как короткий интерфейс к основным командам. Три приложения находятся в независимых Go-модулях `api`, `ingestion` и `bot`; команды Go нужно запускать из каталога соответствующего модуля.

## Требования

- Docker с поддержкой Compose;
- Go 1.27 для запуска и проверки модулей без Docker;
- [Task](https://taskfile.dev/docs/installation) — необязательно, все команды можно выполнить напрямую через `docker compose`.

## Переменные окружения

Docker Compose ожидает отдельный env-файл для каждого приложения. Создайте локальные файлы из шаблонов:

```bash
cp api/.env.template api/.env
cp ingestion/.env.template ingestion/.env
cp bot/.env.template bot/.env
cp osrm/.env.template .env
```

Файлы `.env` не коммитятся. Сейчас шаблоны приложений пусты, потому что их итоговые параметры конфигурации ещё не закреплены. Корневой `.env` управляет опубликованным портом OSRM:

```dotenv
OSRM_HTTP_PORT=5000
```

Внутри сети Compose приложения должны обращаться к маршрутизатору по адресу `http://osrm:5000`; переменная меняет только порт на хосте.

PBF-выгрузка карты также не коммитится. До сборки OSRM создайте `osrm/data` и сохраните выгрузку Санкт-Петербурга как `osrm/data/SanktPetersburg.osm.pbf`. Требования к файлу и порядок обновления описаны в [инструкции OSRM](../osrm/README.md).

## Текущее состояние запуска

Локальный OSRM можно собирать независимо. Полный стек пока не запускается: Go-модули ещё не содержат исполняемых файлов, ожидаемых их Dockerfile, а прикладные зависимости и переменные окружения сервисов не реализованы полностью. Текущее ограничение запуска самого OSRM описано в его README.

Собрать и запустить OSRM:

```bash
docker compose up --build -d osrm
```

После первой сборки для него определены команды запуска и остановки через Taskfile:

```bash
task osrm:up
task osrm:down
```

Подготовка пешеходного графа при первом запуске требует до 1 ГБ оперативной памяти. Состояние подготовки и сервера видно в журнале:

```bash
docker compose logs -f osrm
```

Подробности о данных, volume и HTTP-запросах приведены в [инструкции OSRM](../osrm/README.md).

## Базы данных

Для целевого стека определены две независимые PostgreSQL/PostGIS:

```bash
task api-db:up
task ingestion-db:up
# или обе сразу
task db:up
```

API использует порт `5432` хоста, ingestion — `5433`. Данные сохраняются в volumes `api_db_data` и `ingestion_db_data`.

Обычная остановка сохраняет данные:

```bash
task db:down
```

`docker compose down -v` удаляет volumes обеих баз и подготовленный граф OSRM. Используйте эту команду только когда локальные данные больше не нужны.

## Проверки Go-модулей

Проверки выполняются отдельно для каждого реализуемого модуля:

```bash
cd ingestion
go test ./...
```

Аналогично команды запускаются из `api` или `bot`, когда в соответствующем модуле появляется проверяемый код. Общего `go.mod` в корне намеренно нет.
