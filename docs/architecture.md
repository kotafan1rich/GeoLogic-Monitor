# Архитектура системы

GeoLogic Monitor состоит из четырёх приложений и инфраструктурных компонентов. Подробные внутренние решения принадлежат документации конкретного сервиса; здесь зафиксированы только границы и взаимодействие системы.

## Компоненты

| Компонент | Ответственность | Данные и зависимости |
| --- | --- | --- |
| `miniapp` | Интерфейс точек, рейтинга и истории внутри MAX | Вызывает пользовательские методы API |
| `api` | HTTP-контракт, постоянные данные, геокодинг, рейтинг и планировщик | PostgreSQL/PostGIS, DaData и OSRM |
| `ingestion` | Загрузка инфраструктуры и событий, мониторинг изменений | API, внешние источники и собственный временный кэш |
| `bot` | Webhook MAX, `/start`, чтение уведомлений и отправка сообщений | API, MAX и Kafka |
| `osrm` | Пешеходная маршрутизация по локальному OSM-графу | Вызывается API |

`api`, `ingestion` и `bot` — независимые Go-модули со своими `go.mod`, конфигурацией и Dockerfile. `miniapp` — отдельное приложение React/TypeScript. Межмодульное взаимодействие проходит через HTTP- и Kafka-контракты.

## Взаимодействие

```text
Предприниматель ↔ MAX ↔ Mini App → API → PostgreSQL/PostGIS
                      Bot ───────→ API → DaData / OSRM
                       ↑            ↑
                     Kafka ← ingestion → внешние источники
```

- Mini App передаёт подписанные MAX initData и работает только с данными текущего пользователя.
- Bot регистрирует личный чат пользователя в API и читает задания на уведомления из Kafka.
- Ingestion загружает постоянные данные через внутренние HTTP-методы API; его БД используется только для собственного кэша.
- API единолично обращается к OSRM и предоставляет ingestion пакетный метод расстояний.

Ingestion обнаруживает изменения окружения, публикует типизированные задания в Kafka, а Bot доставляет уведомления в зарегистрированный личный чат MAX.

## Владение контрактами и данными

- [OpenAPI](../api/docs/openapi.yaml) — пользовательские и внутренние HTTP-методы.
- [AsyncAPI](asyncapi/notifications.yaml) — сообщения Kafka.
- Постоянные продуктовые данные и их миграции принадлежат `api`.
- Временный кэш ingestion и его миграции принадлежат `ingestion`.
- `bot` и `miniapp` не обращаются к базам данных напрямую.

Такое разделение сохраняет автономность сервисов: изменение схемы БД не становится неявным контрактом для соседнего приложения.
