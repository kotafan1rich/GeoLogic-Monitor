# Рейтинг окружения точки

Сохраняется алгоритм geo_logic_api_go: подготовка признаков из repository/rating/queries/location_features.go и калькулятор service/rating/calculator.go. Единица расчёта теперь TrackedLocation, без привязки к аренде. Расчёт выполняет ingestion.

## Подготовка признаков

1. Получить через внутренний API точку, BusinessType и InfraType, а также инфраструктуру в радиусе типов.
2. Уточнить расстояния OSRM с пешеходным графом. За пределами MaxRadius объекты исключаются.
3. Сгруппировать объекты по InfraType и собрать InfraTypeFeatures: количество, минимум и среднее расстояний, сумму расстояний, количества в пределах 100/300/500 м и Influence.
4. IsCompetitor истинен, когда TypeID совпадает с BusinessType.InfraTypeID. Вес и радиус берутся из InfraType.
5. Передать LocationFeatures с TrackedLocationID и BusinessTypeID калькулятору.

Свежий кэш 2ГИС дополняет группу конкурентов для этой точки. Полнота конкурентного окружения зависит от загруженной инфраструктуры: выборка «открылись вчера» сама по себе не является полным каталогом конкурентов. При совпадении с постоянным объектом загрузчик должен исключить двойной учёт; до подтверждённого сопоставления источники конкурентов для одной категории не смешиваются.

## Исходная формула

```text
influence = Σ max(0, 1 - distance/maxRadius)²
contribution = weight × log1p(influence)
raw = Σ positive_contributions - Σ competitor_contributions
rating = 10 / (1 + exp(-raw))
result = clamp(round(rating × 10) / 10, 0.1, 9.9)
```

Расстояние и MaxRadius — в метрах, weight и MaxRadius положительные. Для отрицательного raw сохраняется устойчивая ветвь старого кода: 10 × exp(raw) / (1 + exp(raw)).

В старой формуле Event не является отдельным слагаемым. События инициируют уведомления, которые получают актуальный рейтинг инфраструктурного окружения; новый способ включения мероприятий в формулу не придумывается. Причины и рекомендации описывают конкретное изменение отдельно от рейтинга.

5 — нейтральный результат, ниже 5 — преобладание конкурентного вклада, выше 5 — положительной инфраструктуры. Это вспомогательный показатель доступных данных, а не прогноз выручки. В Kafka поле называется location_rating. Нет отдельных коэффициентов сигнала, LOW/MEDIUM/HIGH и нового endpoint просмотра рейтинга пользователем.

## Настройки и проверки

Значения Weight и MaxRadius загружаются ingestion в InfraType, конкретные значения ещё предстоит согласовать. Сопоставление рубрик 2ГИС типам инфраструктуры также требует настройки.

Сохранить тесты старого калькулятора: без признаков — 5; weight=2, influence=1 для положительной инфраструктуры — 8; для конкурента — 2; равные противоположные вклады — 5. Проверить агрегирование нескольких объектов, округление, границы, конечность результата и отмену context. Расчёт по одному новому объекту не заменяет рейтинг окружения.
