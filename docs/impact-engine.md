# Рейтинг окружения точки

API рассчитывает рейтинг при создании точки и по расписанию, используя инфраструктуру из своей БД и пешеходные расстояния OSRM. Формула нормализована по доступным категориям и не сравнивает точку с другими локациями. Это прозрачная MVP-оценка окружения, а не прогноз выручки.

## Смысл шкалы

Шкала центрирована вокруг нейтральной оценки `5`:

- `0–2` — очень плохая локация;
- `3–4` — ниже среднего;
- `5` — обычная, нейтральная локация;
- `6–7` — хорошая;
- `8–9` — очень хорошая;
- `9.9` — исключительная.

Инфраструктура может поднять или понизить оценку относительно `5`. Прямые конкуренты вычитаются отдельно. Поэтому отсутствие объектов рядом само по себе не означает минимальный рейтинг, а насыщенная инфраструктура без дополнительной калибровки не приводит к `9.9`.

## Конфигурация

Файл `api/rating.yml` содержит 40 категорий: вес `w`, радиус `R` в метрах и порог насыщения `k`. Путь задаётся через `RATING_CONFIG_PATH` (по умолчанию `rating.yml` относительно рабочего каталога API). Файл включён в Docker-образ; для изменения без пересборки его можно смонтировать в контейнер. После изменения требуется перезапуск API.

Параметры итоговой шкалы:

```yaml
base_score: 5
infra_baseline: 0.05
infra_spread: 0.08
infra_range: 3.5
competition_max_penalty: 2.5
scale: 10
min: 0.1
max: 9.9
round_factor: 10
```

- `base_score` — baseline нейтральной локации; в текущей модели `5` означает обычную локацию.
- `infra_baseline` — сырой infrastructure score, соответствующий примерно обычной локации.
- `infra_spread` — изменение raw score, достаточное для перехода от среднего уровня к очень плохому или очень хорошему.
- `infra_range` — максимальное влияние инфраструктуры на итоговый рейтинг в пунктах.
- `competition_max_penalty` — максимальный штраф прямых конкурентов в пунктах рейтинга.
- `min` и `max` — только нижний и верхний clamp результата; `round_factor=10` задаёт округление до одного знака.

`infra_baseline=0.05` и `infra_spread=0.08` — начальная калибровка MVP. В будущем их следует корректировать по распределению raw score реальных точек Санкт-Петербурга, не добавляя для этого скрытых коэффициентов в код.

При запуске проверяются конечность всех чисел, `base_score` внутри допустимых границ, `infra_baseline >= 0`, `infra_spread > 0`, `infra_range >= 0`, `competition_max_penalty >= 0`, а также уникальность slug, ссылки на категории, неотрицательные веса и relevance, положительные радиусы и пороги насыщения, границы результата и коэффициентов. Неизвестные YAML-поля и несколько YAML-документов считаются ошибкой.

`available_types` — явный список доступных датасетов. Тип без датасета исключается из положительного числителя и знаменателя. Отсутствие объектов рядом не означает отсутствие датасета. Если положительный знаменатель равен нулю из-за недоступных категорий либо нулевых весов/relevance, калькулятор сохраняет защитный результат `min` и `confidence=0`, а не выдаёт обычную baseline-оценку.

`profiles` задаёт множители релевантности по slug бизнеса:

```yaml
profiles:
  restaurant:
    hotel: 1.3
    pvz: 0
```

Пропущенный множитель равен `1`. Чистая функция также принимает необязательный профиль, переопределяющий конфигурацию, и `streetFactor` в диапазоне `0.85–1` (по умолчанию `1`). HTTP эти параметры пока не принимает, в БД они не хранятся.

## Подготовка данных

1. Получить BusinessType и slug прямых конкурентов.
2. Одним PostGIS-запросом выбрать инфраструктуру через `ST_DWithin` на geography в радиусе максимального `R` из YAML.
3. Запросить расстояния OSRM Table пакетами не более 99 целей и сохранить порядок ответов.
4. Пропустить объекты с отдельным `null` (маршрута нет). При общей ошибке OSRM прервать расчёт без сохранения частичного результата.
5. Передать slug бизнеса и пары «slug объекта — расстояние OSRM» в чистую функцию. Прямое расстояние используется только для пространственного отбора; Haversine и detour-множитель в формулу не входят.
6. Добавить время расчёта в UTC вне чистой функции и сохранить итог в `rating_history`. Создание точки и первой записи истории атомарны.

## Формула

Для каждого доступного типа влияние расстояния линейно убывает до нуля на границе радиуса:

```text
influence_t = Σ max(0, 1 − walkingDistance / R_t)
sat_t = 1 − exp(−influence_t / k_t)
weight_t = w_t × relevance_t
```

Квадрат distance factor не используется. Насыщение `sat_t` остаётся в диапазоне `[0, 1]`, поэтому дополнительные объекты одной категории дают убывающий прирост.

Прямой конкурент — категория с тем же slug, что и `BusinessSlug`. Она не участвует ни в положительном числителе, ни в положительном знаменателе. Для остальных доступных категорий:

```text
rawInfraScore =
    Σ(weight_t × sat_t)
    / Σ(weight_t)
```

Далее raw score переводится в эффект относительно нейтральной точки:

```text
infraNormalized = clamp(
    (rawInfraScore − infra_baseline) / infra_spread,
    −1,
    1
)
infraEffect = infra_range × infraNormalized
```

Конкуренция использует то же насыщение категории бизнеса:

```text
competitionScore = sat_business
competitionPenalty = competition_max_penalty × competitionScore
```

`CompetitionPenalty` в `RatingAssessment` — количество пунктов рейтинга, вычтенное до итогового clamp, а не относительный коэффициент. Если конкурентный датасет недоступен, штраф равен нулю; это не подтверждает отсутствие конкурентов.

Итог при стандартном `streetFactor=1`:

```text
rating = base_score + infraEffect − competitionPenalty
rating = clamp(rating, min, max)
rating = round(rating × round_factor) / round_factor
```

Для внутреннего необязательного `streetFactor` сначала корректируется инфраструктурная часть: `(base_score + infraEffect) × streetFactor`, затем вычитается конкурентный штраф. Поэтому значение `CompetitionPenalty` остаётся фактически вычитаемым числом пунктов.

При текущей калибровке:

- пустое окружение с нормальным положительным знаменателем: `5 + 3.5 × ((0 − 0.05) / 0.08) ≈ 2.8`;
- `rawInfraScore = 0.05`: примерно `5` до конкурентов;
- `rawInfraScore >= 0.13`: `8.5` до конкурентов;
- высокая конкуренция может вычесть не более `2.5` пункта, например снизить `8.5` примерно до `6.0`.

## Confidence и breakdown

`confidence` — отношение доступного положительного веса к полному положительному весу профиля. Категория бизнеса исключается из обеих сумм. Это показатель покрытия данных, а не часть рейтинга и не статистическая достоверность.

Breakdown содержит до `breakdown_limit` положительных вкладов `weight × sat / denominator`. Он не переводится в пункты итогового рейтинга. Вклады сортируются по убыванию, при равенстве — по slug. При одинаковом входе результат детерминирован; чистая функция не использует часы, БД или сеть.

Публичные HTTP DTO не изменены. В историю сохраняются только рейтинг и время. Данные кэша 2ГИС из ingestion и события в формулу не входят.

## Плановый пересчёт и история

Планировщик API вызывает тот же сервис расчёта с актуальными объектами и расстояниями. `RATING_RECALC_CRON` — пятичастное cron-расписание; по умолчанию `0 3 1 * *` в часовом поясе Europe/Moscow. Запуск происходит только по cron, без пересчёта при старте API.

Один экземпляр API выполняет планировщик; перекрывающийся запуск пропускается. Точки обрабатываются последовательно, каждый успешный результат сохраняется отдельно. Ошибка OSRM или калькулятора не перезаписывает прежний рейтинг и не останавливает остальные точки. При остановке API работа отменяется через context.

`GET /api/v1/tracked-locations/{id}/rating-history?months=3` возвращает сохранённые значения за период по возрастанию времени без агрегации и интерполяции. История не переписывается: новая формула применяется при создании точки и очередном пересчёте, поэтому на границе перехода возможен скачок.

## Проверки

Тесты покрывают пустое окружение, baseline и верхний инфраструктурный уровень, линейное влияние расстояния, насыщение, монотонность положительной инфраструктуры и конкурентов, максимальный штраф, сочетание хорошей инфраструктуры с высокой конкуренцией, available types, profiles, confidence, breakdown, защиту нулевого знаменателя, валидацию конфигурации, детерминизм и отмену context.

Benchmark чистой функции:

```bash
cd api
go test ./internal/service/calculate -run '^$' -bench BenchmarkFormulaCalculator1000Objects -benchmem
```

Цель — менее 5 мс на точку без SQL и OSRM.
