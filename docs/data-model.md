# Владение данными

GeoLogic Monitor не использует общую базу для всех сервисов. Каждый сервис владеет своей схемой и миграциями, а обмен постоянными данными проходит через контракты.

[ER-диаграмма](diagrams/rendered/er-model.svg)

## API

API хранит постоянные продуктовые данные:

- пользователей MAX и зарегистрированные чаты;
- отслеживаемые точки;
- типы бизнеса и инфраструктуры;
- объекты инфраструктуры и события;
- историю рейтинга.

Для координат используется PostGIS. Текущий рейтинг определяется последней записью истории, а история удаляется вместе с точкой. Поля, ограничения, индексы и транзакционные правила описаны в [модели данных API](../api/docs/data-model.md).

## Ingestion

Ingestion использует отдельную PostgreSQL для временного кэша конкурентов. Идентификаторы точек и типов поступают через HTTP-контракт API.

Кэш не является постоянной историей продукта и не копирует таблицы API. Его назначение и жизненный цикл описаны в [документации ingestion](../ingestion/README.md).

## Остальные приложения

`bot` и `miniapp` собственной базы не имеют и работают через API. Подготовленный граф маршрутизации включён в Docker-образ OSRM и является инфраструктурным артефактом, а не продуктовой моделью данных.

Такое владение исключает скрытую связанность по таблицам: изменения постоянной схемы контролирует API, а изменения кэша — ingestion.
