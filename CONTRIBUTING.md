# Правила работы с репозиторием

## Ветки

- `main` хранит только проверенный функционал. Делать коммиты напрямую в `main` запрещено.
- `dev` — ветка для объединения результатов выполненных задач.
- Для каждой задачи создаётся отдельная ветка от актуальной `dev`. Не объединяйте несколько несвязанных задач в одной ветке.
- Название ветки должно отражать задачу. Используйте формат `<тип>/<краткое-название>`, например `feature/location-monitoring`, `fix/event-notifications` или `docs/repository-rules`. Если у задачи есть номер, его можно включить в название: `fix/42-event-notifications`.

## Порядок работы над задачей

1. Перед началом проверьте, не работает ли другой участник с тем же кодом.
2. Создайте отдельную ветку задачи от актуальной `dev`.
3. Выполните изменения и необходимые для задачи проверки.
4. После завершения создайте Pull Request из ветки задачи в `dev`. Укажите задачу, суть изменений и результаты проверок.
5. Переносите функционал из `dev` в `main` только после проверки, через отдельный Pull Request.

## Пересекающиеся изменения

Если задача затрагивает код, который уже меняет другой участник, не начинайте правки молча.

- Предпочтительный вариант — не менять занятый участок и создать отдельную задачу на исправление или доработку.
- Если без изменения этого участка текущую задачу не завершить, дождитесь завершения работы другого участника либо заранее предупредите его и согласуйте, кто и что будет менять.
- Согласование должно произойти до начала правок. Не перезаписывайте чужие изменения и не включайте их в свою задачу без договорённости.

Эти правила действуют для всех участников проекта, в том числе при работе с помощью AI-агентов.
