# Безопасность Mini App

Mini App выполняется в недоверенной клиентской среде. Код, состояние React и все значения в браузере могут быть изменены пользователем, поэтому авторизация и бизнес-правила обеспечиваются API.

[OpenAPI пользовательских методов](../../api/docs/openapi.yaml) · [Безопасность API](../../api/docs/security.md)

## MAX initData

MAX Web App SDK предоставляет строку `window.WebApp.initData`. Mini App не извлекает из неё user ID и не проверяет подпись локально. Каждый запрос к пользовательским методам API передаёт исходную строку в заголовке `X-Max-Init-Data`.

API проверяет HMAC-подпись с помощью `MAX_BOT_TOKEN`, обязательные поля и возраст данных запуска. Только после этого сервер использует MAX user ID. Клиентская проверка могла бы улучшить сообщение об ошибке, но не являлась бы границей безопасности, поэтому она не дублируется.

При отсутствии `initData` запросы не отправляются. Ответ `401` означает недействительную или истёкшую сессию: приложение прекращает загрузку данных и просит пользователя заново открыть Mini App через MAX.

## Секреты и запросы

В Mini App нет `MAX_BOT_TOKEN`, сервисных токенов Bot или Ingestion и ключа DaData. Эти секреты принадлежат серверным сервисам и не должны попадать в JavaScript bundle или frontend env-файлы.

Клиент вызывает только относительные URL `/api/v1`. В production Nginx или Caddy проксирует их в API на том же origin. `fetch` выполняется с `credentials: omit`, поэтому cookies не используются для аутентификации, и с `cache: no-store`, чтобы браузер не переиспользовал ответы с пользовательскими данными.

`API_PROXY_TARGET` применяется только локальным Vite server. Переменная загружается без префикса `VITE_` и не экспортируется в клиентский код.

## Пользовательские данные

В памяти страницы временно находятся:

- MAX `initData` из SDK;
- список и история точек пользователя;
- название, категория, адрес и координаты создаваемой точки.

Mini App не записывает эти данные в `localStorage`, `sessionStorage`, IndexedDB или cookies. После перезагрузки вкладки локальное состояние теряется, а данные повторно запрашиваются у API.

Геолокация запрашивается только по явному нажатию пользователя. Координаты отправляются в API для обратного геокодирования; при отказе пользователь может выбрать адрес через поиск.

## Защита интерфейса

Пользовательские значения выводятся стандартными React-элементами, которые экранируют текст. Приложение не использует `dangerouslySetInnerHTML` и не исполняет HTML из API.

Идентификатор точки кодируется через `encodeURIComponent` перед включением в URL. Все мутации блокируются на время выполнения, чтобы не отправлять повторные запросы из одного интерфейса. Эти меры улучшают корректность клиента, но API всё равно обязан проверять принадлежность точки, входные DTO и допустимость операции.

## Границы и ограничения

- `initData` доступно JavaScript в течение жизни страницы; сторонний или внедрённый скрипт с доступом к origin сможет его прочитать.
- Страница загружает MAX Web App SDK с внешнего домена `st.max.ru`; его доставка находится за пределами репозитория.
- В текущей конфигурации Nginx не заданы собственные CSP и дополнительные security headers.
- Клиентский таймаут в 30 секунд не гарантирует отмену уже начатой серверной операции, поэтому после неопределённой ошибки создания следует обновить список перед повтором.
- Защита от доступа к чужим точкам, ограничение срока `initData`, CORS и необходимое ограничение частоты запросов должны обеспечиваться API и внешним reverse proxy, а не Mini App.

Сырые `initData` содержат авторизационный материал. Их нельзя добавлять в URL, аналитику, журналы, сообщения об ошибках, скриншоты или репозиторий.
