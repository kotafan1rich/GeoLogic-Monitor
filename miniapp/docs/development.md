# Разработка и запуск Mini App

## Требования

- Node.js 22;
- npm и зафиксированный `package-lock.json`;
- доступный GeoLogic Monitor API для запросов данных;
- актуальные MAX `initData` для авторизованной ручной проверки;
- Docker Compose — для рекомендуемого запуска полного сценария.

## Установка зависимостей

```bash
cd miniapp
npm ci
```

Используйте `npm ci`, чтобы установить версии из lock-файла без его изменения.

## Запуск через Vite

```bash
cd miniapp
npm run dev
```

По умолчанию приложение доступно на <http://localhost:5173/>, а запросы `/api` проксируются на <http://127.0.0.1:8080>. Если API работает по другому адресу, создайте игнорируемый Git файл `miniapp/.env.local`:

```dotenv
API_PROXY_TARGET=http://127.0.0.1:8080
```

`API_PROXY_TARGET` читается только конфигурацией dev server и не попадает в браузерную сборку. Production-клиент всегда использует относительный путь `/api/v1`.

Обычное открытие URL Vite позволяет проверить сборку и экран отсутствующей авторизации. Для запросов к API приложение должно быть открыто в MAX, который предоставляет `window.WebApp.initData`; вручную подставленные идентификаторы пользователя авторизацией не являются.

## Запуск с Docker Compose

Подготовьте конфигурацию API и из корня репозитория выполните:

```bash
cp api/.env.example api/.env
docker compose up --build -d postgres osrm api miniapp caddy
docker compose logs -f api miniapp caddy
```

Доступные адреса:

- <http://localhost/> — Mini App через Caddy;
- <http://localhost:8083/> — Nginx Mini App напрямую;
- <http://localhost:8080/> — API;
- <http://localhost:8080/docs/> — Swagger UI.

И Caddy, и Nginx Mini App проксируют `/api/*` в контейнер API. При запуске через Compose отдельный адрес backend для frontend не задаётся.

## Проверки и сборка

```bash
cd miniapp
npm run lint
npm run build
```

- `npm run lint` запускает `tsc -b --pretty false` со строгими правилами и проверками неиспользуемого кода;
- `npm run build` повторяет проверку TypeScript и создаёт production-файлы в `miniapp/dist`;
- `npm run preview` локально раздаёт уже собранный каталог, но не настраивает proxy к API.

Пользовательский сценарий проверяется вручную внутри MAX с доступным API по инструкции из [корневого README](../../README.md#как-тестировать).

## Структура

| Путь | Назначение |
| --- | --- |
| `src/App.tsx` | Навигация, общие данные и операции создания/удаления |
| `src/screens/` | Пользовательские экраны |
| `src/components/` | Переиспользуемое отображение, сейчас SVG-график |
| `src/api.ts` | Типизированные вызовы API и единая обработка ошибок |
| `src/max.ts` | Получение `initData` из MAX SDK |
| `src/types.ts` | Локальные копии DTO и UI-состояния |
| `src/rating.ts` | Форматирование времени и изменения рейтинга |
| `src/index.css` | Общие стили и адаптация под мобильный viewport |
| `nginx.conf` | Раздача production-сборки и proxy `/api` |

При изменении HTTP-контракта одновременно обновляйте [OpenAPI](../../api/docs/openapi.yaml), серверные DTO API и соответствующие типы и вызовы в `src/types.ts` и `src/api.ts`.

## Диагностика

- Показан экран «Откройте GeoLogic через MAX»: SDK не предоставил `initData`; откройте Mini App из настроенного MAX-бота.
- После запуска появился экран истёкшей сессии: API вернул `401`; заново откройте Mini App и проверьте одинаковый `MAX_BOT_TOKEN` в MAX и API, а также `MINIAPP_INIT_DATA_MAX_AGE`.
- Vite возвращает ошибку соединения: запустите API и проверьте `API_PROXY_TARGET` в `.env.local`.
- Адреса не находятся: проверьте `DADATA_API_KEY` и доступность интеграции на стороне API.
- Геолокация недоступна: разрешите доступ к местоположению в MAX/браузере; пользователь может продолжить через поиск адреса.
- Создание точки завершается `503`: проверьте доступность OSRM и внешних провайдеров API.
- После изменения исходников production-контейнер показывает старую версию: пересоберите образ `docker compose up --build -d miniapp`.

Токены, сырые `initData` и данные реальных пользователей не следует помещать в `.env.local`, журналы, скриншоты или коммиты.
