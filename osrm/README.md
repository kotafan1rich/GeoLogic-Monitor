# OSRM

Этот каталог содержит локальный OSRM-сервер для расчёта пешеходных расстояний по Санкт-Петербургу. OSRM не отображает карту и не предоставляет тайлы: он строит маршруты по данным OpenStreetMap и возвращает расстояния и продолжительность пути через HTTP API.

## Состав

- `data/SanktPetersburg.osm.pbf` — необязательная локальная выгрузка OpenStreetMap; каталог `data` не коммитится.
- `cmd/prepare.sh` — entrypoint, который подготавливает граф и затем запускает OSRM.
- `docs/http-api.md` — параметры Route/Table API и правила обработки ответов.
- `Dockerfile` — образ с инструментами подготовки и сервером `osrm-routed`.

## Сборка графа

Граф строится при запуске контейнера и сохраняется в Docker volume `osrm_graph`:

1. При сборке Dockerfile копирует локальный `data/SanktPetersburg.osm.pbf`, а при его отсутствии скачивает городскую выгрузку Санкт-Петербурга с BBBike. В образе файл сохраняется как `/source/SanktPetersburg.osm.pbf`.
2. `prepare.sh` проверяет маркер `/data/.prepared-v26.9.0-foot` в volume.
3. Если граф отсутствует или PBF-файл новее маркера, `osrm-extract` читает карту с профилем `/opt/foot.lua` и записывает пешеходный граф в `/data`.
4. `osrm-partition` делит граф на ячейки для алгоритма MLD.
5. `osrm-customize` рассчитывает метрики маршрутизации.
6. `osrm-routed --trial=true` проверяет, что подготовленный граф можно загрузить.
7. После успешной проверки создаётся маркер, а entrypoint через `exec` запускает команду из `CMD` — постоянный сервер `osrm-routed`.

Если подготовка или проверка завершится с ошибкой, сервер не запустится. Для подготовки и запуска используется одна и та же закреплённая версия OSRM — `v26.9.0-debian`.

Volume сохраняется при остановке, удалении и повторном создании контейнера. Поэтому при обычном перезапуске готовый граф используется повторно и не строится заново. Команда `docker compose down -v` удалит `osrm_graph` вместе с остальными volumes проекта, включая volumes баз данных.

## Запуск

Дополнительная подготовка PBF не требуется. При сборке образа городская выгрузка Санкт-Петербурга автоматически скачивается с BBBike:

```bash
docker compose build osrm
```

Чтобы использовать собственную совместимую выгрузку, до сборки сохраните её как `osrm/data/SanktPetersburg.osm.pbf`. Dockerfile проверяет этот путь и скачивает файл только при его отсутствии.

Создать корневой `.env` с настройками Docker Compose:

```bash
cp osrm/.env.template .env
```

Внешний порт OSRM задаётся переменной:

```dotenv
OSRM_HTTP_PORT=5000
```

Внутри Docker-сети OSRM всегда слушает порт `5000`; эта переменная изменяет только порт, опубликованный на хосте. Если корневой `.env` отсутствует или переменная не задана, Compose использует `5000` по умолчанию.

Собрать образ и запустить OSRM:

```bash
docker compose up --build -d osrm
```

После первой сборки образ можно запускать через Taskfile:

```bash
task osrm:up
```

Задача `osrm:up` не передаёт флаг `--build`. После изменения `Dockerfile` или `cmd/prepare.sh` снова выполните команду `docker compose up --build -d osrm`.

При первом запуске HTTP-сервер станет доступен только после завершения подготовки графа. Последующие запуски используют граф из `osrm_graph`.

Посмотреть журнал:

```bash
docker compose logs -f osrm
```

После запуска OSRM доступен:

- другим контейнерам сети `geo_logic_net` по адресу `http://osrm:5000`;
- с хоста по адресу `http://localhost:${OSRM_HTTP_PORT}`.

## Проверка

Пример запроса пешеходного маршрута:

```bash
curl 'http://localhost:5000/route/v1/foot/30.315868,59.939095;30.335098,59.934280?overview=false'
```

Для рейтинга используется Table API, позволяющий одним запросом получить расстояния от точки до нескольких объектов:

```bash
curl 'http://localhost:5000/table/v1/foot/30.315868,59.939095;30.335098,59.934280;30.327000,59.936000?sources=0&destinations=1;2&annotations=distance'
```

В примерах используется порт из шаблона. Если `OSRM_HTTP_PORT` изменён, его нужно заменить и в URL. Координаты передаются в порядке `longitude,latitude`. Значения `distances` возвращаются в метрах, а `null` означает, что маршрут между точками не найден.

Подробное описание endpoint, параметров и ответов находится в [документации HTTP API](docs/http-api.md).

## Обновление карты

Чтобы обновить данные:

1. Пересобрать образ без Docker-кэша, чтобы скачать актуальную выгрузку:

```bash
docker compose build --no-cache osrm
docker compose up -d osrm
```

Локальный `data/SanktPetersburg.osm.pbf` имеет приоритет над автоматической загрузкой. Чтобы снова использовать BBBike, удалите локальный файл перед сборкой. Если исходный PBF новее маркера в volume, `prepare.sh` перестроит граф.

Чтобы принудительно перестроить граф без удаления volume с базами данных, нужно удалить только маркер и перезапустить OSRM:

```bash
docker compose run --rm --entrypoint sh osrm \
  -c 'rm -f /data/.prepared-v26.9.0-foot'
docker compose restart osrm
```

Профиль маршрутизации является частью графа. После изменения профиля или версии OSRM нужно изменить имя маркера либо удалить старый маркер и перестроить граф.
