# OSRM

Этот каталог собирает локальный OSRM-сервер для расчёта пешеходных расстояний по Санкт-Петербургу. API использует OSRM Route и Table API при расчёте Smart Score и расстояний для уведомлений. OSRM не отображает карту и не предоставляет тайлы.

## Состав и данные

- `Dockerfile` — двухэтапная сборка графа и runtime-образа;
- `data/SanktPetersburg.osm.pbf` — необязательная локальная выгрузка OpenStreetMap;
- `docs/http-api.md` — используемые методы Route и Table API;
- `.dockerignore` — исключает локальные файлы и включает PBF только по ожидаемому пути.

По умолчанию Dockerfile скачивает региональную выгрузку `RU-SPE.pbf` с `https://www.osmlab.ru/regions/RU-SPE.pbf`. Для воспроизводимой сборки с заранее подготовленными данными сохраните совместимый файл как `osrm/data/SanktPetersburg.osm.pbf`: локальный файл имеет приоритет над загрузкой.

## Как собирается образ

Граф строится во время Docker build:

1. Builder устанавливает `curl` и сертификаты.
2. Локальный PBF копируется в `/source`, а при его отсутствии скачивается URL из build argument `PBF_URL`.
3. `osrm-extract` обрабатывает данные с пешеходным профилем `/opt/foot.lua`.
4. `osrm-partition` и `osrm-customize` готовят граф для алгоритма MLD.
5. `osrm-routed --trial=true` проверяет, что граф загружается.
6. Каталог `/graph` копируется в минимальный runtime-образ, который запускает `osrm-routed` на порту `5000`.

Готовый граф является частью образа. При запуске контейнера карта не скачивается и граф не перестраивается; отдельный runtime volume для OSRM не используется.

## Сборка и запуск

Создайте корневой файл окружения:

```bash
cp .env.example .env
```

Соберите и запустите сервис:

```bash
docker compose up --build -d osrm
docker compose logs -f osrm
```

Переопределить источник карты при прямой сборке можно через build argument:

```bash
docker build --build-arg PBF_URL=<PBF_URL> -t geologic-osrm ./osrm
```

Внутри Compose-сети сервис всегда доступен по адресу `http://osrm:5000`. С хоста используется `http://localhost:${OSRM_HTTP_PORT}`, где `OSRM_HTTP_PORT=5000` задан в корневом `.env.example`.

## Проверка

Маршрут между двумя точками:

```bash
curl 'http://localhost:5000/route/v1/foot/30.315868,59.939095;30.335098,59.934280?overview=false'
```

Матрица расстояний от одной исходной точки до двух объектов:

```bash
curl 'http://localhost:5000/table/v1/foot/30.315868,59.939095;30.335098,59.934280;30.327000,59.936000?sources=0&destinations=1;2&annotations=distance'
```

Координаты передаются в порядке `longitude,latitude`. Значения `distances` возвращаются в метрах, а `null` означает отсутствие пешеходного маршрута. Подробности приведены в [описании HTTP API](docs/http-api.md).

## Обновление карты

Если используется удалённый `PBF_URL`, принудительно загрузите актуальную выгрузку и перестройте граф без Docker cache:

```bash
docker compose build --no-cache osrm
docker compose up -d osrm
```

Для контролируемой версии данных замените `osrm/data/SanktPetersburg.osm.pbf` и пересоберите образ. После изменения PBF, версии OSRM или пешеходного профиля требуется новая сборка образа; перезапуска старого контейнера недостаточно.

## Ресурсы и ограничения

- первая сборка требует сетевого доступа, если локальный PBF не предоставлен;
- время сборки зависит от размера карты и ресурсов Docker;
- runtime-контейнер не обновляет карту автоматически;
- OSRM рассчитывает маршруты по данным конкретной PBF-выгрузки, поэтому дата её получения определяет актуальность дорожного графа.
