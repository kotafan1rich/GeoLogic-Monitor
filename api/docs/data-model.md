# Модель данных API

API владеет постоянными данными GeoLogic Monitor. `bot` и `ingestion` не обращаются к этой базе напрямую: обмен идёт через HTTP-контракт.

[ER-диаграмма](../../docs/diagrams/rendered/er-model.svg) · [Миграции](../migrations) · [OpenAPI](openapi.yaml)

## Общие правила

- Поля и ограничения таблиц сверяются с миграциями [`../migrations`](../migrations). Типы и связи также показаны на ER-диаграмме.
- В колонке «NULL» указано, допускается ли отсутствие значения. `—` в колонке «По умолчанию» означает отсутствие SQL DEFAULT: обязательное значение задаёт приложение, необязательное можно оставить NULL.
- Внутренние идентификаторы — `uuid`, идентификаторы MAX — `bigint`, внешние идентификаторы источников — `text`.
- `timestamptz` хранит момент времени; через HTTP время передаётся в UTC. Календарные границы рассчитываются в `Europe/Moscow`.
- `geometry(Point,4326)` хранит координаты WGS 84 в порядке `lon,lat`. HTTP использует именованные `lat` и `lon`. Поиск расстояний в метрах выполняется через `location::geography`.
- `created_at` и `updated_at` — технические поля, не возвращаемые через HTTP. Во всех существующих таблицах API `updated_at` автоматически обновляется триггером при UPDATE.
- `PRIMARY KEY` и `UNIQUE` создают соответствующие уникальные индексы. Дополнительные индексы перечислены под таблицами. FK `rating_history.tracked_location_id` имеет `ON DELETE CASCADE`; у остальных FK API действие при удалении — `NO ACTION`.

## База данных API

### `users` — пользователи

Пользователи MAX и личные чаты для уведомлений.

| Поле | Описание | NULL | По умолчанию |
| --- | --- | --- | --- |
| `id` | PRIMARY KEY; внутренний идентификатор. | Нет | `gen_random_uuid()` |
| `max_user_id` | UNIQUE; CHECK > 0. Идентификатор пользователя MAX. | Нет | — |
| `max_chat_id` | Идентификатор личного чата уведомлений; регистрируется ботом через /start. | Нет | — |
| `created_at` | Время создания записи. | Нет | `now()` |
| `updated_at` | Время последнего изменения; обновляется триггером. | Нет | `now()` |

Ключ регистрации пользователя — `max_user_id`. Дополнительных индексов нет.

### `tracked_locations` — точки пользователя

Один пользователь может отслеживать несколько точек.

| Поле | Описание | NULL | По умолчанию |
| --- | --- | --- | --- |
| `id` | PRIMARY KEY; внутренний идентификатор. | Нет | `gen_random_uuid()` |
| `user_id` | FK → users.id; владелец точки. | Нет | — |
| `business_type_id` | FK → business_types.id; тип бизнеса. | Нет | — |
| `name` | CHECK btrim(name) <> ''; пользовательское название точки. | Нет | — |
| `address` | CHECK btrim(address) <> ''; адрес точки. | Нет | — |
| `location` | Координаты точки. | Нет | — |
| `created_at` | Время создания записи. | Нет | `now()` |
| `updated_at` | Время последнего изменения; обновляется триггером. | Нет | `now()` |

Индекс: B-tree `(user_id)`; поле не уникально. Удаление точки физическое. История рейтинга удаляется каскадно; независимый кэш ingestion исчезает при TTL-очистке. Rent и его производные не используются.

### `infra_types` — типы инфраструктуры

Справочник категорий с legacy-полями веса и радиуса. Новая формула рейтинга берёт параметры из `api/rating.yml`.

| Поле | Описание | NULL | По умолчанию |
| --- | --- | --- | --- |
| `id` | PRIMARY KEY; внутренний идентификатор. | Нет | `gen_random_uuid()` |
| `slug` | UNIQUE; CHECK btrim(slug) <> ''. Стабильный ключ типа. | Нет | — |
| `name` | CHECK btrim(name) <> ''; название категории. | Нет | — |
| `weight` | CHECK > 0; legacy-вес справочника, не используется новой формулой рейтинга. | Нет | — |
| `max_radius` | CHECK BETWEEN 1 AND 65535; legacy-радиус справочника в метрах, не используется новой формулой рейтинга. | Нет | — |
| `created_at` | Время создания записи. | Нет | `now()` |
| `updated_at` | Время последнего изменения; обновляется триггером. | Нет | `now()` |

Upsert выполняется по `slug`. Жизненный цикл справочника основан на сохранении и обновлении стабильных записей.

### `business_types` — типы бизнеса

Связь типа бизнеса с категорией инфраструктуры, определяющей прямых конкурентов.

| Поле | Описание | NULL | По умолчанию |
| --- | --- | --- | --- |
| `id` | PRIMARY KEY; внутренний идентификатор. | Нет | `gen_random_uuid()` |
| `infra_type_id` | UNIQUE; FK → infra_types.id. Категория прямых конкурентов. | Нет | — |
| `created_at` | Время создания записи. | Нет | `now()` |
| `updated_at` | Время последнего изменения; обновляется триггером. | Нет | `now()` |

Upsert выполняется по `infra_type_id`. Название для Mini App берётся из `infra_types.name`. Начальные варианты — кофейня, кафе и ресторан; их загружает ingestion, ID не зашиваются в клиент. Дополнительных индексов нет.

### `infra_objects` — объекты инфраструктуры

Постоянная инфраструктура, используемая для расчёта рейтинга.

| Поле | Описание | NULL | По умолчанию |
| --- | --- | --- | --- |
| `id` | PRIMARY KEY; внутренний идентификатор. | Нет | `gen_random_uuid()` |
| `external_id` | UNIQUE; CHECK btrim(external_id) <> ''. Стабильный идентификатор загрузчика. | Нет | — |
| `type_id` | FK → infra_types.id; категория инфраструктуры. | Нет | — |
| `location` | Координаты объекта. | Нет | — |
| `address` | CHECK btrim(address) <> ''; адрес объекта. | Нет | — |
| `name` | Название объекта. | Да | — |
| `created_at` | Время создания записи. | Нет | `now()` |
| `updated_at` | Время последнего изменения; обновляется триггером. | Нет | `now()` |

Индексы: B-tree `(type_id)`, GiST `((location::geography))`. Upsert выполняется по `external_id`; внутренний UUID генерируется БД и не передаётся при upsert. Загрузчик обеспечивает стабильность внешнего идентификатора; это не идентификатор карточки 2ГИС.

### `events` — мероприятия

События рядом с точками пользователей.

| Поле | Описание | NULL | По умолчанию |
| --- | --- | --- | --- |
| `id` | PRIMARY KEY; внутренний идентификатор. | Нет | `gen_random_uuid()` |
| `provider` | CHECK btrim(provider) <> ''; источник события. | Нет | — |
| `external_id` | CHECK btrim(external_id) <> ''; идентификатор события у источника. | Нет | — |
| `location` | Координаты события. | Нет | — |
| `date` | Дата и время события; в HTTP поле также называется date. | Нет | — |
| `info` | Название и текст мероприятия. | Да | — |
| `notified_at` | Время завершения публикации уведомлений всем подходящим точкам. | Да | — |
| `created_at` | Время создания записи. | Нет | `now()` |
| `updated_at` | Время последнего изменения; обновляется триггером. | Нет | `now()` |

Уникальность и ключ upsert: `(provider, external_id)`. Индексы: B-tree `(date)`, GiST `((location::geography))`. Модель события содержит источник, внешний идентификатор, координаты, дату, описание и отметку публикации.

`events.notified_at` означает завершённую публикацию уведомлений для подходящих точек, а не доставку сообщения в MAX. API предоставляет внутренние методы для выборки неотмеченных событий и установки отметки; upsert не сбрасывает уже записанное значение.

Ingestion выбирает необработанные события, публикует задания для подходящих точек в Kafka и после завершения публикации записывает `notified_at`. Контракт не ведёт таблицу отдельных доставок: при частичном сбое и повторной обработке возможен повтор части сообщений, что соответствует семантике доставки как минимум один раз.

### `rating_history` — история рейтинга

Каждый успешный расчёт формирует отдельную запись.

| Поле | Описание | NULL | По умолчанию |
| --- | --- | --- | --- |
| `id` | PRIMARY KEY; идентификатор записи истории. | Нет | — |
| `tracked_location_id` | FK → tracked_locations.id ON DELETE CASCADE; точка расчёта. | Нет | — |
| `value` | CHECK BETWEEN 0.1 AND 9.9; рейтинг с одним знаком после запятой. | Нет | — |
| `calculated_at` | Время успешного расчёта; возвращается через HTTP. | Нет | — |
| `created_at` | Время создания записи. | Нет | `now()` |
| `updated_at` | Время последнего изменения; обновляется триггером. | Нет | `now()` |

Индекс: B-tree `(tracked_location_id, calculated_at)`.

Создание точки и первой записи истории выполняется в одной транзакции. Каждый успешный плановый расчёт добавляет запись, включая неизменившиеся значения; неудачный расчёт ничего не записывает. Текущий рейтинг — последняя запись по `calculated_at`; отдельная копия рейтинга в tracked_locations не нужна.

История хранится до удаления точки. Период выборки по умолчанию — последние три календарных месяца, а не TTL. Границы периода вычисляются в Europe/Moscow, при вычитании месяцев день ограничивается последним днём целевого месяца. Старые точки без истории получают первый рейтинг при следующем плановом запуске; до этого пользовательский API возвращает `rating: null` и `rating_calculated_at: null`. Исторические значения задним числом не восстанавливаются.

## Принятые решения

- UUID используются как внутренние идентификаторы, а внешние идентификаторы MAX и поставщиков хранятся отдельно.
- Пространственные данные хранятся в PostGIS, чтобы грубо отбирать кандидатов в метрах; пешеходное расстояние затем уточняет OSRM.
- Текущий рейтинг не дублируется в `tracked_locations`: им считается последняя запись истории.
- Создание точки и первого рейтинга выполняется транзакционно, а история удаляется каскадно вместе с точкой.
- Каждая миграция принадлежит API и автоматически применяется сервисом при старте.
