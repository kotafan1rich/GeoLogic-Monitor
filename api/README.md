# GeoLogic Monitor API

API — центральный сервис GeoLogic Monitor. Он владеет постоянными данными продукта, предоставляет пользовательские и внутренние HTTP-методы, рассчитывает рейтинг окружения и ведёт его историю.

Для пользователя сервис поддерживает поиск адреса, работу с точками, справочник типов бизнеса и историю рейтинга. Для `bot` он регистрирует MAX-пользователя и чат. Для `ingestion` принимает справочники, инфраструктуру и события, отдаёт точки для мониторинга и рассчитывает пешеходные расстояния.

## Место в системе

```text
MAX Mini App ── пользовательские методы ──┐
bot ─────────── регистрация чата ─────────┼── API ── PostgreSQL/PostGIS
ingestion ───── внутренние методы ────────┘   ├── DaData Suggest
                                               └── OSRM
```

API выбран владельцем постоянных данных, чтобы `bot` и `ingestion` не зависели от его схемы БД. Сервисы взаимодействуют по версионированному HTTP-контракту, а временный кэш ingestion остаётся в отдельной базе.

## Возможности

- автоматическое применение миграций при старте;
- регистрация MAX-пользователя и чата служебным запросом от `bot`;
- проверка подписанных MAX initData для запросов Mini App;
- подсказки и обратное геокодирование через DaData;
- создание, просмотр и удаление точек пользователя;
- расчёт первого рейтинга в одной транзакции с созданием точки;
- история рейтинга и плановый пересчёт всех точек;
- загрузка справочников, инфраструктуры и событий из `ingestion`;
- пакетный расчёт пешеходных расстояний через OSRM;
- OpenAPI и Swagger UI.

## Быстрый запуск

Из корня репозитория:

```bash
cp api/.env.example api/.env
docker compose up -d postgres osrm
docker compose up --build -d api
curl http://localhost:8080/health
```

Эквивалентная команда Task:

```bash
task api:up
```

Swagger UI доступен по адресу <http://localhost:8080/docs/>, спецификация — в [`docs/openapi.yaml`](docs/openapi.yaml).

Для запуска без Docker нужны доступные PostgreSQL/PostGIS и OSRM, корректный `api/.env` и рабочий каталог `api`:

```bash
cd api
go run ./cmd/api
```

Миграции из `migrations/` применяются автоматически. API не запустится при неверной конфигурации рейтинга, недоступной БД, ошибке миграции или отсутствии обязательных переменных окружения.

## Архитектурные решения

- API обслуживает Mini App, выполняет плановый пересчёт рейтинга и предоставляет пользовательские и внутренние методы.
- Планировщик выполняется в единственном экземпляре API, что обеспечивает последовательный ежемесячный пересчёт.
- Создание точки зависит от доступности OSRM: при общей ошибке маршрутизации транзакция откатывается.
- Формула рейтинга является прозрачной оценкой окружения и отделена от прогноза выручки.
- Точки сохраняют выбранные при создании адрес, категорию и радиусы расчёта; обновление рейтинга выполняет планировщик.
