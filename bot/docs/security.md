# Безопасность Bot

Bot пересекает три границы доверия: принимает webhook MAX, вызывает GeoLogic Monitor API и отправляет сообщения через MAX Bot API. Для каждой границы используется отдельный секрет.

[OpenAPI регистрации пользователя](../../api/docs/openapi.yaml) · [AsyncAPI уведомлений](../../docs/asyncapi/notifications.yaml)

## Входящий webhook MAX

При старте Bot передаёт `WEBHOOK_URL` и `WEBHOOK_SECRET` в MAX и подписывается на `message_created` и `bot_started`. Входящие обновления принимаются только на `POST /webhook`.

Официальный MAX SDK сравнивает заголовок `X-Max-Bot-Api-Secret` с настроенным `WEBHOOK_SECRET` и возвращает `401 Unauthorized` при несовпадении. После проверки SDK декодирует update, поэтому `user_id` и `chat_id` используются только из принятого MAX-события, а не из пользовательских заголовков или тела произвольного API-запроса.

Webhook должен быть доступен по HTTPS. Секрет следует задавать случайным непустым значением и менять одновременно в конфигурации Bot и подписке MAX.

## Доступ к MAX Bot API

`MAX_BOT_TOKEN` используется официальным клиентом для регистрации webhook и отправки сообщений. Этот токен принадлежит Bot, не передаётся Mini App и не используется как сервисный токен API.

Токен обязателен для запуска. Его нельзя помещать в URL, сообщения, журналы или клиентскую сборку Mini App.

## Регистрация пользователя в API

Для `PUT /api/v1/users/me` Bot отправляет:

- `Authorization: Bearer <BOT_SERVICE_TOKEN>` для аутентификации сервиса;
- `X-Max-User-Id` со значением из проверенного MAX update;
- `max_chat_id` в JSON-теле из того же update.

Заголовок `X-Max-User-Id` сам по себе не авторизует запрос: API требует одновременно корректный `BOT_SERVICE_TOKEN`. Mini App этот токен не получает. Полный формат запроса, ответы и коды ошибок определены в [OpenAPI](../../api/docs/openapi.yaml).

## Разделение секретов

| Секрет | Где используется | Что защищает |
| --- | --- | --- |
| `WEBHOOK_SECRET` | MAX → Bot | Подлинность входящего webhook |
| `MAX_BOT_TOKEN` | Bot → MAX | Управление подпиской и отправка сообщений |
| `BOT_SERVICE_TOKEN` | Bot → API | Доступ к регистрации пользователя и чата |

Секреты не взаимозаменяемы. `BOT_SERVICE_TOKEN` должен совпадать с настройкой API, а `MAX_BOT_TOKEN` — с токеном бота, которому принадлежит webhook и Mini App.

## Логирование и данные

Bot журналирует служебные идентификаторы чата, точки и субъекта уведомления, но не должен журналировать токены, webhook secret или полные входные payload. Локальный `bot/.env` не коммитится; в репозитории хранится только шаблон со значениями-заглушками.

Bot не хранит собственную базу пользователей или историю уведомлений. Постоянные сведения о пользователе и чате сохраняются API, а Kafka offset отражает только состояние обработки очереди.
